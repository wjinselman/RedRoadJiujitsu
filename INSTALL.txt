Red Road: Simple Parent Links

1. In the existing Red Road Firebase project, open Firestore Database > Rules. Publish the contents of FIREBASE/firestore.rules. This is a rules update, not an SDK version upgrade. No database reset, account recreation or data migration is needed.
2. Upload the HTML, JS and CSS files at the top of this ZIP to the website root, replacing matching files. The FIREBASE folder is for the Firebase console; uploading it to GitHub does not publish the rules.
3. Refresh the Staff Dashboard. In Families, select Spencer's existing member account in Parent / existing member, then Save Parent Link for each child. His current email is preselected when it matches. No new parent account or billing category change is needed.

Behavior
- The dropdown includes existing roster members and parents who have submitted child profiles. It is not filtered by billing category.
- Saving the parent link approves the child. Linked children can check in when the parent's membership is active, portal-enabled and not archived. Parent deactivation blocks all linked children; reactivation restores access without editing each child.
- During Kids hours, the parent can select one or multiple children. During adult hours, a training parent can check themselves in. For adult self-check-in their program must be Adult or Family, not the non-training Parent / Payer program.
- Only owners and developers can change parent links. Other parents cannot read or check in unrelated children. Reassigning a parent moves account access to the selected verified email, preserving the original waiver signer information.
- Existing billing records and payment amounts are unchanged. This does not create new accounts or charge anyone.

Validation
19 targeted UI/logic tests and 16 isolated Firestore emulator checks passed. Attendance-rule tests use a test-only pinned server clock; the release rules retain the real server clock. Parent selector preview inspected in the browser. No live member records or attendance were changed.
